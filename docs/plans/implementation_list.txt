/cb-green — Add kk-useradd / kk-userlist / kk-passwd CLIs that create users in auth.db and mirror them into the Reviewer roster in master.db

  - What: Make users creatable from the command line, and make every created
    user automatically appear on the existing reviewer roster. This is the
    bootstrap path for the first admin, and it is the mechanism that lets a
    later prompt delete the reviewer dropdown.

    Design context (settled, do not re-litigate — plan §3 D-6, D-7, D-9):
    The operator offered to REMOVE the reviewer roster entirely. That option is
    REJECTED. Rationale: HumanReview nodes carry a reviewed-by edge to Reviewer
    nodes, so the roster is the graph-side record of authorship — removing it
    would force master.db to depend on auth.db to answer "who wrote this
    review", inverting the storage separation. Removal would also touch ~10
    source/test files and ~9 spec nodes and is a refactor of shipped behaviour
    requiring separate rule-#4 approval. Instead the roster becomes a
    PROJECTION of the user list: creating a user creates its roster entry.
    The roster name IS the auth username (D-7). Usernames are unique by primary
    key in auth.db, so INV-KK-REVIEWER-NAME-UNIQUE (case-insensitive, enforced
    at src/ingest/reviewer_registry.py:24-37) can never be violated by user
    creation. A separate display name is deliberately deferred.
    Users are DEACTIVATED, never deleted (D-9): a deleted user whose reviews
    still reference their roster entry leaves dangling attribution.

        username non-empty and not already present; post: a row exists in

    D-1 PARENT GATE, CHILD MOUNT. One structural choke point, mirroring the
    existing WEB_MUTATION_ALLOWLIST pattern at src/web/routes.py:27-36. A
    middleware also covers FastAPI's auto-generated /docs, /redoc and
    /openapi.json, which per-route dependencies would silently miss.

    D-11 NO HARDENING: no rate limiting, no CSRF tokens, no password reset, no

        kk_remember cookie + remember_tokens row exist iff "remember me" was
